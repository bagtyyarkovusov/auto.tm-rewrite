# ADR-0018: API runs on port 3006 in development

- **Status**: Accepted
- **Date**: 2026-05-17

## Context

The monorepo runs four HTTP services in local development under `turbo run dev`:

- API (NestJS) — originally on port 3000
- Admin (Next.js) — on port 3001
- Web (Next.js public marketing + listings) — on port 3002
- SMS gateway adapter (when run locally) — on port 3007

Port 3000 collides routinely with other tooling on developer machines: Next.js scaffolds default there, Storybook does, Create React App does, many sample apps do. We hit this in practice during S2 — agents and contributors regularly tried to start the API only to find port 3000 occupied by an unrelated process from a different project, leading to confusing "server doesn't respond" failures that were really port-bind failures.

Picking a port that is (a) not 3000, (b) not adjacent to 3001/3002 where a typo would silently hit the wrong service, and (c) above the privileged-port boundary (1024) but below the ephemeral-port range gave us a small shortlist. We chose **3006**.

This decision was already executed across the codebase in commit `a29914b` (2026-05-17, cherry-picked from PR #62), but the *why* was never captured in an ADR. New contributors and agents currently see "3006" hardcoded across `.env.template` files, `apps/api/src/main.ts`, `apps/mobile/src/api/client.ts`, the Caddyfile, the deployment runbook, and the OpenAPI spec — with no documented reason. This ADR closes that gap.

## Decision

**The API listens on port 3006 in local development.** This is the value baked into every workspace's `.env.template`, `apps/api/src/env.schema.ts` default, `apps/api/src/main.ts` fallback, the mobile `apiClient` base URL, and the API healthcheck commands in the deployment runbook.

In TM staging and production, the API still listens on 3006 inside its container, but external traffic is fronted by Caddy reverse proxy at `api.auto.tm` — the port number is an implementation detail invisible to callers.

Sister-service dev ports (kept for completeness):
- `3001` — admin (Next.js)
- `3002` — web (Next.js)
- `3006` — api (NestJS) — this ADR
- `3007` — sms gateway adapter (when run locally)

The `turbo.json` `dev` task was updated in the same commit to `dependsOn: ["^build"]` so runtime-shared workspace packages (`@auto-tm/db`, `@auto-tm/contracts` — see ADR-0016) are built before any `turbo run dev` invocation. That change is related but not the topic of this ADR.

## Consequences

### Positive

- No port-bind collisions against the dozens of other dev tools that default to 3000 on a typical developer's machine.
- The two-digit gap from 3001/3002 means a typo (`30001` vs `30006`) hits a bind error, not the wrong service.
- `curl localhost:3006/healthz` is the canonical local healthcheck for the API and matches the runbook verbatim.

### Negative / accepted costs

- New developers and agents have to remember 3006 rather than the default 3000. Mitigated by `.env.template` defaults and the runbook.
- Any third-party documentation or tutorial that assumes NestJS-default 3000 must be mentally remapped. Low frequency, low cost.
- Forcing port-3006 in CI means CI containers must not have anything else on 3006 — true today, monitored at sprint-close.

### Neutral

- No production behavior change (Caddy reverse proxy abstracts the port).
- No SDK/contract change.

## Alternatives considered

- **Keep 3000.** Rejected: ongoing collisions with unrelated tooling burned real debugging time in S2.
- **Randomize per-developer (e.g., `PORT=$(shuf -i 30000-40000)`).** Rejected: every `.env`, runbook command, and CI script would have to read the random port back, multiplying config sprawl. The shared port is a feature, not a bug — everyone's `curl localhost:3006/healthz` works the same.
- **Move admin/web off 3001/3002 and put the API on 3000.** Rejected: admin and web have been on 3001/3002 since S1; moving them now would invalidate bookmarks, runbooks, screencast tutorials, and existing `.env` files for every contributor.
- **Use 3003-3005 (closer to admin/web).** Rejected: closer numerical adjacency increases typo-mistake risk. 3006 is far enough to be unambiguous.
