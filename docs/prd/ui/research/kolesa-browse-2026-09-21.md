# Kolesa browse observations, 2026-09-21

> Noncanonical observational research. This note records what first-party Kolesa sources showed on 2026-09-21. It does not change [ADR-0034](../../../adr/0034-kolesa-ux-findability-reference.md), the [Kolesa findability reference](../kolesa-findability-reference.md), or any AutoTM design spec. Live listing counts and promotion blocks change frequently.

## What was actually checked

I inspected Kolesa's public desktop-web [cars results page](https://kolesa.kz/cars/), a [Toyota Camry results page](https://kolesa.kz/cars/toyota/camry/), and a [listing detail page](https://kolesa.kz/a/show/230191010). I also read Kolesa's own [guide to finding cars](https://kolesa.kz/content/kak-bystro-nahodit-nuzhnye-avto-na-kolesa-kz/), its [mobile-app promotion page](https://kolesa.kz/promo/mobile/), and the developer's [Google Play listing](https://play.google.com/store/apps/details?id=kz.kolesa). These are first-party product pages or a developer-authored store listing. I inspected the live accessibility tree of the [mobile website's cars page](https://m.kolesa.kz/cars/) in a browser. I did **not** install or operate the current native Android/iOS app. I did not test filter-control behavior by clicking through it.

## Observed desktop-web route

1. **Entry to cars.** Kolesa's cars page has a broad top navigation for Machines, credit, new cars, history, parts, repair/services, commercial vehicles, and articles. Within Machines, it exposes passenger cars, new cars, dealers, motorcycles, and water transport. This is a multi-category marketplace. [Cars page](https://kolesa.kz/cars/)
2. **Filter before results, on the same page.** The cars page renders a filter form above its result count and listings. It includes region, a brand field, new/used condition, photo/history/customs toggles, an extended-search section, body, fuel, gearbox, steering, drive, mileage, availability, engine displacement, color, dealer, keyword, year, price, and finance fields. A "Show N listings" action appears immediately before the results heading. The HTML alone does not prove whether applying the filter navigates, reloads, or updates in place. [Cars page](https://kolesa.kz/cars/)
3. **Brand/model is a drill-in within the native filter, according to Kolesa's guide.** The guide explicitly tells buyers to open the filter and tap "Марка, модель". It documents selecting multiple makes, excluding makes/models, and multiselecting color, body, gearbox, fuel, and drive. The guide includes screenshots, but it does not by itself establish the exact current native home-screen layout, brand search field, popular-model ordering, or whether the native results screen is a separate route. [Kolesa filter guide](https://kolesa.kz/content/kak-bystro-nahodit-nuzhnye-avto-na-kolesa-kz/)
4. **Filtered result state has its own address on web.** `/cars/toyota/camry/` shows a Toyota Camry heading, a result count, sorting by posting date, the same filter form, and listing cards. The URL and heading show that a selected brand/model is represented as a durable result state. This does not prove that selecting a model always opens a new screen in the native app. [Toyota Camry results](https://kolesa.kz/cars/toyota/camry/)
5. **Listing cards lead to detail.** The cars page shows photo/listing entries with make/model, price, year, engine/fuel/transmission, location, date, and a favorite action. Some listings carry paid VIP/promoted placement or credit information, so the default list is not simply a pure chronological feed even though its sort label says posting date. [Cars page](https://kolesa.kz/cars/) The opened [Camry detail](https://kolesa.kz/a/show/230191010) has photos, price, city and specifications, a seller/contact section, options, history-report and owner-review sections, favorite/note/report actions. The machine-readable page did not expose enough interaction detail to assert the exact native contact-bar treatment.

The concise web path is `Machines / cars → filter (brand/model plus other criteria) → counted results → listing detail`. Brand/model can also be entered through Kolesa's visible browse links lower on the cars page. The exact native-screen sequence remains unverified.

## Observed mobile website

The live [mobile cars page](https://m.kolesa.kz/cars/) exposes a category button labelled "Легковые" and a separate "Фильтр" button above a "Найдено N объявлений" count. Under that are VIP offers and a "Результаты поиска" listing section. Its bottom navigation is Kolesa.kz, Favorites, Post, Messages, and Cabinet. This confirms the mobile **website** has a distinct filter entry and results presentation, but it still does not establish the current native app's exact screens or whether filter Apply opens a new route. [Mobile cars page](https://m.kolesa.kz/cars/)

## What the native-app sources support, and what they do not

Kolesa's Google Play description says buyers select a category, search by city/make/price and other parameters, save a search, favorite listings, and message or call sellers. Its mobile promotion page advertises listings alongside new cars, reviews, news, and stories. These support the app's *capabilities*, not the pixel layout or precise current navigation order. [Google Play listing](https://play.google.com/store/apps/details?id=kz.kolesa), [Kolesa mobile page](https://kolesa.kz/promo/mobile/)

The existing AutoTM [findability reference](../kolesa-findability-reference.md) says Kolesa's native home has stories, category tiles, and a recommended feed, and that cars browse has a dedicated Filter entry. That account came from a May 2026 third-party screen-gallery capture plus local founder screenshots. I have not independently reverified those native screens on the September 2026 app. The current first-party evidence therefore supports the **filter funnel and brand/model drill-in**, but not a claim that Kolesa currently uses a personalized home feed or the exact same home/results navigation described in the older reference.

## Implication for the comparison

Kolesa does use brand/model as a prominent, structured search criterion and represents the resulting set clearly with a heading and count. A dedicated AutoTM result screen would be a plausible adaptation of that pattern, but it should be tested as an AutoTM design choice, not described as a confirmed copy of Kolesa's current native flow. The narrower conclusion is more useful than assuming the two apps already match screen for screen.
